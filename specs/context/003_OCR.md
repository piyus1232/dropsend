# Overview

Currently, the receipt upload feature works like a normal image upload, we need to add OCR with gemma4. The OCR must be done only with gemma4 and that too with gemini api on cloud.

The OCR on the bills or receipts must extract the following fields:

1. merchant
2. amount
3. category
4. date
5. paymentMethod
6. currency
7. items billed (array of items with info for each specific one)



any of the field could be null if the agent failed to find/extract it.

The items should not be an jsonb type in the schema as it will further be used for other purposes so it should be a row per item.

## Supabase Schema

Supabase Schema for "extractions" should be there to store the above extarcted info.


## Inngest Worker and Supabase Realtime

Supabase Realtime should be sending the updates as it is doing now to the client as per the upload status of the bill/receipt image.

Inngest worker should be used for OCR on a batch for background processing as it is doing right now.

## IMPORTANT

Right now, the confidence score of each extracted field is out of scope for this feature, we will include it later.

## Layers

Instead of building all at once, build the feature in layers:

1. Layer 01: Start building Supabase Schemas for the receipt.
2. Layer 02: Add gemma4 setup with gemini api, add agent and system prompt and get it reviewed.
3. Layer 03: Add output schemas for agent to give the realible output structure.
4. Layer 04: Wire the agent function with the inngest worker to handle background processing for batch upload.
