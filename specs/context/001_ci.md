# Overview

Currently this project doesn't have any CI/CD pipeline for automatically running linting, type checking, and build scripts when any PR is raised. The goal is to build a CI pipeline through GitHub Actions by creating the workflow file and adding/updating the required scripts in `package.json`.

# Context

This task should trigger CI for all the commands mentioned below:

1. `bun install --frozen-lockfile`
2. `bun run lint`
3. `cd apps/web && bunx tsc --noEmit`
4. `bun run build`

Each command should execute sequentially. If any command fails, the pipeline should fail and clearly report the error from that particular step.

# Trigger Point

The pipeline should be automatically triggered whenever a new Pull Request is opened or updated against the `main` branch.

The workflow should run for PRs targeting:

- `main`

# Packages / Tools to Use

Use the project's existing tooling and do not introduce unnecessary dependencies.

Required tools:

- **ESLint** — for linting via `bun run lint`
- **TypeScript** — for type checking via `bunx tsc --noEmit`
- **Bun** — for dependency installation and running project scripts
- **GitHub Actions** — for the CI workflow

Do **not** add a testing framework or test dependencies because the project currently does not have a test suite.

# Expected Workflow

The GitHub Actions workflow should perform these steps in order:

1. Checkout the repository.
2. Set up the required Bun version.
3. Install dependencies using:
   `bun install --frozen-lockfile`
4. Run linting:
   `bun run lint`
5. Run TypeScript type checking:
   `cd apps/web && bunx tsc --noEmit`
6. Run the production build:
   `bun run build`

Each step should be clearly named in the GitHub Actions workflow so that failures can be easily identified from the GitHub Actions UI.

# Requirements

- Do not push directly to `main`.
- CI should run automatically on every PR targeting `main`.
- Commands must run sequentially.
- The workflow should fail immediately when a required step fails.
- Do not add unnecessary packages or testing frameworks.
- Reuse the project's existing Bun, ESLint, TypeScript, and build configuration.
- Keep the implementation minimal and consistent with the existing project structure.
