# CI

GitHub Actions workflow that runs lint, type checking, and a production build on every pull request targeting `main`.

## Decisions

- **Trigger:** `pull_request` targeting `main` only. No trigger on `push` to `main` — merges are already gated by the PR's own check run.
- **Package manager:** Bun, pinned to `1.3.14` in the workflow to match `packageManager` in `package.json`, rather than resolving the version dynamically.
- **Type-check ordering:** Next.js 15+ generates ambient route types (`LayoutProps`, `PageProps`) into `.next/types` as a side effect of `next dev`/`next build`. A fresh CI checkout has no `.next` directory, so `tsc --noEmit` fails on `LayoutProps` references unless those types exist first. Added a `next typegen` step (generates route types without a full build) immediately before the type check step.
- **Build-time env vars:** `/dashboard`'s layout throws if `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are unset. That route is server-rendered on demand, not statically prerendered, so the build only needs these values to be truthy. Placeholder values are hardcoded directly in the workflow's build step — no real Supabase project or GitHub secret required.
- **Tests:** Not included. The project currently has no test framework or test files; adding one was explicitly out of scope for this task.
- **Branch protection:** Not configured as part of this change. Requiring this check before merge is a repo-admin setting on GitHub, separate from the workflow file itself.

## Workflow (`.github/workflows/ci.yml`)

Trigger: `pull_request` → `main`.

| Step | Command |
| --- | --- |
| Checkout repository | `actions/checkout@v4` |
| Set up Bun | `oven-sh/setup-bun@v2` (`bun-version: 1.3.14`) |
| Install dependencies | `bun install --frozen-lockfile` |
| Run lint | `bun run lint` (→ `turbo lint` → ESLint via `eslint-config-next`) |
| Generate Next.js types | `cd apps/web && bunx next typegen` |
| Run type check | `cd apps/web && bunx tsc --noEmit` |
| Run build | `bun run build` (→ `turbo build` → `next build`), with placeholder Supabase env vars |

Steps run sequentially within a single job. GitHub Actions stops the job on the first failing step by default, so no extra fail-fast configuration is needed.

## Verification

Ran the full sequence locally before opening the PR (install → lint → typegen → typecheck → build) — all steps pass against current `main`.

## Dependencies Added

None. Reuses the project's existing Bun, ESLint (`eslint-config-next`), TypeScript, and Next.js tooling.

## Not Included / Future Work

- Test framework / test step.
- CD (deploy on merge) — the hackathon brief only required CI.
- Branch protection rule requiring this check before merge.
- Dynamic Bun version resolution from `package.json` (currently hardcoded).
